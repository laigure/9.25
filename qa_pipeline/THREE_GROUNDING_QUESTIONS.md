# 3EED Grounding 的三个具体问题（代码与实测）

## 1. 哪个输出是目标 token？

`3EED/models/bdetr.py` 的 `BeaUTyDETR.forward()` 产生 256 个候选 query。每个 decoder 层都会更新这些 query；在第 6（最后）层的输出、送入最终预测头**之前**，可选保存 `end_points["last_query_features"]`，形状 `[B,256,288]`。候选 `j` 的 288 维向量与 `last_center[:,j]`、`last_pred_size[:,j]` 的预测框使用同一个 `j`。因此导出一个目标时，取 `last_query_features[:,j]`；不能将 64 维 `last_proj_queries[:,j]` 错认作问答用的目标 token，后者是文本匹配分支。

这是一个**候选目标 token**，不是模型自动保证的“正确目标 token”。如果选错 `j`，即使取值层位正确，QA 收到的仍是错误物体。

## 2. 它有多少位置信息？

代码可证明位置曾参与生成：点云 `xyz` 经 `pos_embed` 参与视觉/文字 cross encoder；模型从候选 proposal 得到中心和尺寸；当前 `loc_learned` 设置把 `[center,size]` 经学习的位置嵌入加到 decoder query/key，且 decoder 与整句文字及点特征交互。因此最终 288 维 query **受位置影响**。

代码不能证明其 288 维中保留了精确中心或两物体的可比较坐标。当前中性描述 token 的离线线性探针（冻结 token、仅 train 序列拟合）在 v3 val：自车远近 89.37%、自车左右 69.42%、自车联合方位 52.84%、双物体相对位置 30.09%。这是**“当前文字选择器选出的 token + 简单探针”整体能解出的信号**，不能纯粹归因于 token 内容；如果选错 query，探针也会被污染。双物体探针使用 `[a,b,a-b]` 而不只是单个 288 维向量。

早期双物体 QA 测试集（332 题）仅 token 的联合关系正确率 59.94%；另加**预测**中心后 68.37%。这是下游比较，不可直接推断 token 是否含有精确 xyz；说明单靠当前 token+后端不能稳定利用空间信号。

要更清楚分开“token 不含位置”与“选错 token”，下一次审计在同一批未见过的 val 样本上分别测：实际文字 top1 token、仅离线诊断用的 GT-IoU 最佳候选 token、预测中心。分别做中心坐标回归、单目标左右前后/远近、双目标相对位置探针。报告 MAE、分类准确率、候选选对率；GT oracle 仅作上限，不进入最终系统。

## 3. 文字怎样从 256 个候选中选出车？

1. RoBERTa 处理**完整描述**，decoder 让每个候选 query 与文字、点特征交互。
2. 文本 token 与候选 query 各自经过对比投影到 64 维并归一化。
3. 计算每个候选与每个文本词的点积相似度；除以温度 0.07，沿文本词维度 softmax。
4. 当前单目标 Waymo 数据加载器根据 GT 物体类别，在原描述中找**第一个匹配的类别/同义词**（如 car），形成 `positive_map`。评测/官方 token 导出将该词位置的概率相加，给每个 query 一个分数，再取分数最大候选 `j`。`positive_map` 不含 GT 框坐标，也**不是模型自己预测出的自由文本目标片段**；它依赖数据集类别和规则匹配。
5. 导出第 `j` 个最终 288 维 query 和第 `j` 个预测框。GT 框只用于导出后的 IoU 评测，不参与这个 top1 选择。

例：“右边的黑车”：整句话参与网络交互；最后排序通常汇总 `car` 所对应的词概率，并不直接把 `右边/黑` 的概率一起求和。其它词仍可能通过 decoder 改变 query，所以不能说模型完全忽略它们，但这种排序对多辆同类车可能不够强。

已有实测：原始完整 Waymo val 3,782 条，公开 checkpoint 的 Grounding Acc@0.25=80.67%、Acc@0.5=49.89%；中性化去空间提示后，val 3,082 条实际 top1 Acc@0.25=47.50%。两者输入描述和样本集合不同，不可当作严格配对消融。32 条 val pilot 的文字 top1 Acc@0.25=53.1%，文字 top5 包含正确框的 GT 诊断上限 81.3%，全部 256 候选 GT oracle 96.9%；这个小样本只说明候选选择值得重点优化，不能当正式 top5 性能。

从头复现的 3EED Waymo 训练运行状态见 `GROUNDING_REPRO_LOG.md`。公开 checkpoint 和新训练 checkpoint 的数字必须分开报告。
